# Mistakes log

Mistakes in my own reasoning or approach, logged as found. Check before starting work.

- **2026-10-03 — `dist/` is stale.** `dist/` was built on 2025-09-05 by the old Vite setup (`dist/assets/*`), before the Nuxt migration. Don't use it as evidence of what the current build ships; reason from the source instead.
- **2026-10-03 — Misread the scope of a request.** "let's go with calm and fix the highest impact based on your table" meant *fix every item in the table, carefully*, not *fix only the top one*. I did #1 and #10, then stopped and listed the rest as "next". When a request points at a list, do the whole list unless told otherwise; ask only when a specific item needs a decision.
- **2026-10-23 — Recursive grep over node_modules.** Ran `grep -ril` on the whole project and filtered `node_modules` out afterwards; it walked node_modules anyway and timed out. Exclude heavy dirs in the search itself (Grep tool with a glob, or `--exclude-dir`).
- **2026-10-23 — Chose a visible motion direction without saying so.** The spec had no curtain element, so I picked "rings rise from below the viewport" for the entry. I didn't flag that choice, or that it leaves only the icon on screen for about the first half second, in the summary. When I map a spec onto elements that don't match it, state each visible interpretation (direction, what is hidden and for how long) up front.
- **2026-10-23 — Followed a timing spec literally where it hurt the result.** The spec used an ease-in curtain whose blur peaks at the end and then cuts to 0. With no travel to hide it, the rings popped in at full opacity and the blur snapped off at 0.9s. An entrance should start at its most different state (invisible, blurred) and decelerate into rest. Judge the motion as a viewer, not only against the spec numbers.
- **2026-10-24 — Assumed Array.from's map callback gets the array.** Wrote `Array.from({ length }, (_, index, list) => list.length)`; that callback only receives (value, index), so `list` was undefined and the footer crashed. Caught by generating a sample card in Node before handing over. Keep the length in a variable.
- **2026-10-24 — Assumed the CSS `scale` property composes with GSAP.** Put the hover `scale` on the menu buttons, which GSAP animates. GSAP's CSSPlugin bakes the independent transforms into `transform` and writes inline `scale/rotate/translate: none`, so the stylesheet rule never applied. On any element GSAP has tweened, put CSS transforms on a child (or let GSAP drive it) instead.
- **2026-10-24 — Appended a prompt under another session's heading.** Another session had added its own heading after mine in `prompt-history.md`, and I appended my next prompt to the end of the file, under that heading. Insert under my own session's heading, not at the file's end.
- **2026-10-24 — Inverted icons with SVG masks when plain paths would do.** To flip four "disc with logo cut out" icons I used luminance masks over a white disc; the user saw a black background behind them. The logo was already in each path as separate subpaths, so dropping the outer disc subpath (or closing the contour along its arc) gives a plain filled shape with nothing behind it. Prefer editing the path geometry over masks for icons.
- **2026-10-24 — Sized the card container's padding for the thorns, not for the art box.** The `.container` padding (1.5rem on phones) was meant to leave room for the frame, but `.card-frame__art` overflows the card by `--card-frame-overflow` (~44px: longest barb + wobble + shadow room). Inside an `overflow-y: auto` container (which makes overflow-x auto too) that gave a horizontal scroll on small screens. When an absolutely positioned layer overflows its box, check it against every scroll container it sits in, using the real overflow value.
